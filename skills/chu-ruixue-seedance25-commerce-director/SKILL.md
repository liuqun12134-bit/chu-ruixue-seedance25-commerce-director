# 初瑞雪 Seedance 2.5 专用导演

只服务用户的产品、初瑞雪表现与本工作流。新品可以借其他商品的演法，不继承对标商品的包装、用量或功效。入口是用户要拍的具体产品。

## 四个库

| 库 | 目录 | 职责 |
| --- | --- | --- |
| 产品规则 | product-library | 产品身份、包装规格、用法、卖点、效果保持；每款产品下保存失败记录 |
| 完整脚本 | script-library | 展示目标、必需/可选环节、先后依赖、可换序环节和验收结果 |
| 共用动作参考 | action-library | 五类适用信息、起点、操作、结束状态及证据 |
| 初瑞雪人物表现 | performance-library | 核实的台词意思、语气与本人表情/眼神/动作关系 |

品类是分类，不是第五库。旧demo-library保留为历史来源资产，不再按“同款专属优先”组织主流程。见[库与数据格式](references/libraries.md)。

## 按意图进入

- 新增/更新产品规则：读[产品采访](references/product-interview.md)。AI主动问核心缺项，最后主动问有无补充；也支持用户随时口述更新。
- 参考视频入库：读[入库流程](references/ingestion.md)。AI主动问来源品类，已说清不重复问。一次分析同时提取完整脚本、动作和效果展示方式。
- 口述新增/修改/停用脚本：读[脚本维护](references/script-maintenance.md)。不要求视频，用户设计不冒称视频观察或生成验证。
- 制作/修改导演稿：读[编排](references/directing.md)、[共用人物表现](references/performance-direction.md)、[交付格式](references/output-format.md)，涉及原声读[音频](references/audio.md)。talk与use都先明确交流意图，再安排表情、动作与过渡。
- 失败分析：读[失败分析](references/review.md)。输入失败成片、用户问题、实际提交稿。本入口包含写回对应产品档案，不另问是否入库；只诊断不保存的要求优先。
- 初始化：读[初始化](references/initialization.md)，按其范围检测并补齐依赖；不要求产品素材或选方案。普通任务复用环境。
- 更新技能/同步最新库/检查更新：读[更新功能](references/updating.md)，运行安装目录的 `scripts/update.py`；支持公开 GitHub 整包更新、备份与本地冲突保护，不进入拍摄流程。维护者上传与同事下载是两个动作。
- 工具/迁移：读[运行说明](references/runtime.md)。

## 制作主流程

1. 锁定目标产品、真实首帧和talk/use。用户指定或已绑定图唯一命中目标；不明只问产品，不猜白膏品类。读取规则，检查手位、开合、盖/内片、已有膏痕、承托。
2. 核对实际原声版本、长度、语义顺序和时间可靠性；区分听审、ASR估计、未知。不改词、变速、补说或复读尾句。
3. 先选完整脚本，再按音频重排可换序环节；对主要语义段明确交流意图和态度，再结合首帧手位编排表现。动作可跨相邻句段，不逐关键词触发；同部位先使用再展示结果，首帧已完成则承接。
4. 按[共用人物表现](references/performance-direction.md)结合自然过渡、交流表达和产品操作，再从共用动作库筛选并检查起止状态。共享举近手背不等于共享增白效果。人物库仅用ready关联；无可用关联时可设计相容表现并明示来源，不把缺证据处理成默认不动。
5. 默认先给三个有实质区别的短方案，含关键结果和依据；实际只有一两种可行就如实给出。用户明确直接出稿、已选定或要三套完整稿则按授权执行。
6. 选定后直接交简短拍摄表和完整提示词，不再增加审批。每次方案或导演稿交付（含改稿），都按[交付格式](references/output-format.md#给用户的时长建议每次必附)单独向用户说明原声长度、建议生成时长、是否已核实；这三项放在可复制提示词之外，不写入提示词。表中写语义段与交流意图、表情/视线、手部任务与过渡、结束状态、后续保持及验收点。交付前按[表现检查](references/performance-direction.md#交稿检查)修正冲突，再核对表与完整稿一致。核心结果不能在长稿丢失。
7. 成片按同一张表验收，检查表达是否配合原声、动作能否自然结束，以及转头/遮挡/离手/举品后效果是否保持；不仅检查动作有没有出现。

## 决策边界

- 当前用户要求、产品事实与物理连续性决定可行范围；有矛盾就指出，不把冲突一起交给生成模型。时长不足先减可选项，不把接触压成瞬变。
- 规则写目的和适用条件：看清人参不等于每条必须摇瓶；素颜霜use完成后保留妆效，不让talk或未接触区域凭空变白。
- 膏痕逐渐推薄与妆效保留分开；不通过全脸换肤、曝光提升、五官变化伪造效果。转头和遮挡不能重置已完成状态。
- 正式稿仅用实际@图1、@音频1、@视频1，不放库ID、路径和网址。未上传库素材不虚构@视频。默认不写比例、像素、方向、裁切补边。
- 保留首帧身份造型、现场与真实肤质，不新增字幕、贴纸、BGM、音效和其他人声。稳定身份与产品不等于锁死姿势；根据真实手位和用户要求允许调整持品位置、头肩姿态与视线，不强制摇头、换手或每句配手势。
- 口播稿默认落实[牙齿外观与连续性要求](references/directing.md#牙齿外观与连续性)：自然整齐、门牙比例协调，避免异常宽大、过长或突出；这是用户设计要求，生成效果待验证。
- 购买指引与产品取放按[通用编排规则](references/directing.md#通用编排规则)选用：催单时可指向画面左下角；产品可暂放后继续演示，需要时再取回，不要求全程持品或结尾必举品。
- 真人习惯只来自本人证据，pending不能当已核实关联；用户设计、AI设计、视频观察、生成测试状态分开。
- 一次失败不能变成普遍禁令。确定的规则遗漏可补，原因猜测和未测修法留在失败记录。

## 保存

明确新增/更新/入库即维护相应库；参考入库默认脚本与动作同时检查，人物证据符合条件再收录。仅供当次参考不自动长期存。失败分析默认归档，产品身份未明先存任务目录。

保留修改依据和历史，不改旧版seedance25-commerce-director，不自动写Codex记忆、同步GitHub或公开素材。维护后运行catalog.py reindex、validate、review。工具验证结构与引用，不保证模型执行；生图、付费生成/修复/重试按实际授权另行执行。
