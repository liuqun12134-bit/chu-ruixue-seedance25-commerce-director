# 编排与选方案

## 建立本次条件

读实际素材，不按附件顺序猜角色。记录模式、商品及适用部位、开合、画面左右手各持何物、盖与配件、可用承托面、脸上/手上已有膏体。自拍是否镜像未知时以画面左右定位，不擅自确定生理左右。

确认当前音频版本、实测长度、语气、重音和自然停顿；按语义划分“提出问题、体验说明、使用演示、推荐收尾”等本次实际存在的段落，不强套这些段落或机械按每五秒切段。记录各句的时间依据：可靠对齐、ASR 估计、用户稿、未知。音频来源不明或两份可疑版本时，先完成不依赖版本的工作，再只确认关键缺失。

## 从动作单元出发

先读两个索引：[产品/品类](../demo-library/index.json)、[人物表现](../performance-library/index.json)。用 `scripts/catalog.py units --mode use --category 面霜` 展开所有同品类候选，必要时加 `--product-id`。此命令不自动理解部位、包装和手位，不按排列先后推荐，也不保证某单元适合 talk。逐个检查相关的起始条件、接触路径、结束状态和来源限制。

内部留下小型候选表：单元 ID｜是否适用｜理由｜本批次是否用过。无需每轮把整张内部表发给用户。至少比较会改变方案的可行路线，允许筛到零条；不机械要求读某个固定数量。

旧库的观察事实与导演建议分开使用。例如记录写“一手持罐、另一手涂抹”说明该条参考的条件，不代表所有手位都必须如此；“一个局部链”是旧简化策略，不代表其他部位不存在。改路线时要重新说明实际可执行的持物和接触，不能把旧事实改写为相反的观察。

## 按台词调用本人表现

读统一人物索引中的 expression，按本次语义段识别表达类别和语气，再用关键词及相近意思查找 ready 记录。可运行 `catalog.py performances --mode talk --intent 引导购买 --text "喜欢的可以拍了"`；脚本保留同类的全部候选，词面未命中不等于语义不适用。

内部记录“本次原话/语义段 → 表达类别 → 所选表现 → 发起/收势时机”。核对整句是否否定、引用或其他意图，并核对当前空闲手、姿态、持物。将动作安排在对应句段，连续同类说法不机械逐词重复。相同类别可以有多个动作变体；pending 只供补充核查，不能作为已确认的本人话术关联。

## 同时编排操作和表演

每个语义段考虑三类内容，按需要取用，不要求每段齐全：

- **产品任务**：展示、取用、接触、推开、看清结果。
- **对人的交流**：目光回应、重点词的表情/手势、短暂靠近或转头。
- **自然过渡**：说话呼吸间隙、空闲手回落、收势、重新看回镜头、动作后短暂停留。

“看起来没功能”的动作也应符合此人的状态和前后动作；不要把随机摸发、频繁眨眼或全身晃动当自然。没有本人证据时，只做克制的设计补充，并在方案来源处明说。自然表现可以发生在操作之间、操作中或完成后；不把所有空隙都填成继续涂抹。

每条动作形成：起始状态 → 准备/发起 → 接触或交流 → 回收/结束 → 下一段。体现速度、幅度和停顿的变化，不把所有动作写成同速、匀速、到点切换。保持嘴部可交流，不必全程正脸、品牌始终朝镜头或一手永远锁住。

## 模式边界

talk：讲解和交流为主，适时展示。允许有依据的空闲手动作、表情变化和姿态调整，不把“稳定”写成静止。默认不取用/上脸；用户指定的小操作按条件保留，不擅自扩展全流程。

use：至少完成用户要的核心接触/操作及可辨认结果。首帧已开盖就承接，已有膏痕就保持到真实推开。时长不足时减少重复、部位和非必要步骤；时长足够可组合不同合理环节，不把额外时间都变成抹脸。手背不能静默替换用户指定的上脸；没有依据不能扩展到眼周。

产品效果与量按当前产品证据，不凭“面霜”猜颜色、克数、成膜或吸收。长期功效不能演成即时变化。没有匹配参考时可读[通用方法](methods.md)，必须标为设计方法。

## 三方案如何真正不同

同一原音频、商品和首帧条件下，在可执行范围内改变交流与展示的重心、操作路线、动作顺序或节奏；保持文案一致，不编三份新口播。可用“交流为主、演示为主、交流与演示穿插”作为思路，不能变成每次固定三款模板。三套 use 都必须满足使用目标，三套 talk 不能为凑差异擅自上脸。

每套短方案写 4 项：重点；开头/中间/结尾的动作和对应话题；主要参考与证据状态；适合本次的理由及一个关键条件。普通情况每套约 100–180 字即可；关键限制需说清。推荐依据是本次语气、可用手位、时长和本人参考，不是哪个动作最容易重复生成。

默认等用户选 A/B/C 或修改组合后再展开。用户说“直接给完整稿”“你来选”则按授权完成；用户要求三套都能测试时给三份互相独立的完整稿。不能因用户没马上回复而自行视为选中推荐项。

## 参考视频、故事板与文字

- 有匹配本人连续视频且当前提交端确认支持时，可用动作视频传达节奏、停顿、回收和表情；明确只借哪些片段与维度，不复制原商品、场景、声音或额外台词。
- 先核对上传端的实际能力，不宣称 Fish/Seedance 某入口必然支持视频参考、指定权重或任意时长。无支持时用文字动作和已有关键帧。
- 路线复杂或用户要检查关键状态时，先交简短镜头/状态表；确需故事板图且用户已授权生图时另走生图工具。静态故事板擅长说明位置与顺序，不能证明动态习惯。
- 不默认同时塞很多图、故事板和视频。按难点选择必要参考；人物库素材仅用于内部阅读时，不能在正式稿写成已上传的 `@视频1`。

## 定稿核对

核对所选方案的核心动作、顺序、交流方式、关键停顿、收尾是否都出现在正式稿中；每段手位、配件、膏体首尾是否相容。对比原声语义与动作时长，不让句子去迁就动作。明确选方案后发现条件不成立时指出具体冲突，保留可行部分再调整，不悄悄还原为旧单一路线。
