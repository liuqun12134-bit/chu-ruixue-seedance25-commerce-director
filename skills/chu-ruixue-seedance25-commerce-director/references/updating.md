# 从 GitHub 更新技能与库

适用于“更新初瑞雪技能”“同步最新库”“检查更新”。用户请求更新即执行下面的更新入口；只有“检查”时使用 `--check`。这不是产品规则编辑，不进入采访或三方案。普通出稿不自动联网更新，不设置后台任务。

固定来源为公开仓库 https://github.com/liuqun12134-bit/chu-ruixue-seedance25-commerce-director 的 `main` 分支，包目录 `skills/chu-ruixue-seedance25-commerce-director`。下载不要求 GitHub 账号；维护者推送仍使用自己的账号。不要改成旧版导演技能或其他仓库。

## 同事使用

在**实际安装的本技能目录**运行，复用初始化时可用的 Python 3.10+。还需要 Git；执行更新需要 Git LFS。缺工具时先说明缺项并补齐可用安装，不把下载失败当作已是最新，不索取令牌。

```text
python scripts/update.py --check
python scripts/update.py
```

默认目标是脚本所在技能目录，跨目录调用不依赖当前工作目录。不要在临时下载副本里运行后声称实际安装已更新。确需指定目标时传 `--skill-dir "实际安装目录"`。

- `--check` 读取远端发布清单，与本地逐文件比较；不下载 LFS 视频、不改安装文件或升级基线。会使用临时下载、状态目录和排他锁。
- 更新获取固定提交的技能、四库、旧来源档案和全部媒体；验证 LFS、发布清单 SHA-256 及库结构。临时副本中合并并重建索引、生成清单，验证成功后才替换安装目录。
- 同事本地独有的文件保留。已建立基线后，上游单独修改或删除的文件跟随更新；仅本地修改的文件保留。双方改动同一文件则停止整次更新，列出冲突；不自动覆盖、重置或按文本拼接库记录。索引与总览是派生文件，合并后重建。
- 完整旧目录保留为同级 `chu-ruixue-seedance25-commerce-director.backup-时间-标识`，不自动清理。准备足够空间容纳下载、暂存副本和备份。验证失败保留原安装；替换失败立即尝试恢复旧目录。出现进程强杀/断电时核对备份与锁，不盲目删除。
- 状态与上游文件哈希保存在 `%USERPROFILE%/.codex/runtimes/chu-ruixue-seedance25-commerce-director/updates/`，遵循 `CRX_RUNTIME_DIR`，也可用 `--state-dir` 指定。状态不进入技能包。不要把状态从另一安装路径直接复制过来。

## 首次接入与旧安装

首次安装/更新没有基线：与上游同路径同内容的文件可接入，本地独有文件保留，上游新增文件可补齐；同路径内容不一致则停止，不能猜哪一版应覆盖。

旧版没有更新入口，同事先完整安装一次带本功能的新版本（先备份，保留本地内容、解决同路径差异）。复制完成后运行已安装目录的 `scripts/update.py`，验证并登记基线。以后只需说“更新初瑞雪技能和所有库”。若首次接入报告冲突，比较并明确合并或恢复冲突文件后重跑，不能把“没有基线”当作强制覆盖的理由。

已建立基线的冲突：报告文件、当前提交及建议保留内容；待实际解决后重新执行。不要删除基线绕过冲突。维护者在自己的安装里有尚未推送改动时同样受保护，更新入口只下载、不推送。

## 结果与恢复

退出码 0=检查/更新成功，2=有冲突未应用，1=依赖、网络或验证等失败。JSON 中 `updated` 才表示替换成功，`up_to_date` 表示文件无需更新，`available` 只表示存在可应用变化，`conflicts`/`failed` 不得宣称完成。向用户简报版本、提交短码、更新文件数、保留的本地改动或冲突、备份路径；提示必要时新开对话重新加载技能。

回退时停止使用技能，确认目标和备份都在同一技能父目录；把当前目录另存后恢复完整备份。若已有旧基线，将状态目录中对应 `.before-备份名.json` 一并恢复为该安装的状态文件；首次更新没有旧基线则移开新状态重新接入。恢复后运行 `catalog.py validate`。不要只回退代码、留下新库或新基线。

## 维护者发布

本地入库仍不自动推送。维护者明确要求同步 GitHub 时，将整个技能目录同步到仓库的 `skills/chu-ruixue-seedance25-commerce-director`，包括本更新脚本、四库和所有引用素材；维护版本号，并**重新生成仓库根目录的 `package-manifest.json`**（每个文件的路径、大小、SHA-256 和总数/字节数），再运行 `tools/verify_package.py`、`catalog.py validate`、`git lfs fsck`，推送清单、技能和 LFS 对象到 `main`。不要沿用旧清单，否则更新器会拒绝安装。更新是否可用按提交及文件哈希判断，不仅比较版本号，因此只新增库也能更新。

公开仓库的文件可被任何人下载；发布内容以维护者本次授权范围为准。本更新器不上传同事的本地内容，也不改机器音频环境。
